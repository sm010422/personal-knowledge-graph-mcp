# ADR-0004: 관계 타입을 닫힌 집합으로 제한

- 상태: Accepted
- 날짜: 2026-10-19

## 맥락

관계를 만드는 주체는 LLM이다. 관계 타입을 자유 문자열로 열어두면 같은 의미가 `BUILT`, `MADE`, `WORKED_ON`, `DEVELOPED`로 흩어진다. 그러면 "내가 만든 프로젝트" 질의가 일부만 찾는다.

## 선택지

1. **자유 문자열**: 유연하지만 어휘가 표류한다.
2. **닫힌 enum + 방향 규칙**: 어휘는 고정되고, 새 관계가 필요하면 코드 변경(이 ADR 갱신)이 필요하다.
3. **자유 문자열 + 사후 정규화**: Phase 4 수준의 작업이 필요하다.

## 결정

2번. `RelationType` enum 12개와, 관계마다 허용되는 (from 타입, to 타입) 규칙(`RELATION_RULES`)을 둔다. 다른 것이 맞지 않을 때를 위해 `RELATED_TO`(any → any)를 탈출구로 둔다.

## 결과

- 툴 스키마에 enum이 들어가서 LLM이 선택지를 보고 고른다. description에 각 관계의 방향도 적었다.
- `USES`를 Technology → Project로 거꾸로 걸면 허용 방향을 알려주는 에러가 난다. LLM이 바로 고쳐서 재호출할 수 있다.
- `RELATED_TO` 남용은 Phase 3 메트릭(관계 타입별 생성 수)으로 관찰하고, 자주 쓰이는 패턴이 보이면 새 타입으로 승격한다.
- 관계 타입은 Cypher에 문자열로 보간되지만, enum 값만 들어가므로 인젝션 위험이 없다.
