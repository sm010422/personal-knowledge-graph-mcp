# ADR-0002: 저장소로 Neo4j 5 Community 사용

- 상태: Accepted
- 날짜: 2026-10-19

## 맥락

핵심 질의는 "이 엔티티 주변 1~2단계에 무엇이 있나"(`get_context`)다. 예: 이 프로젝트 → 쓰는 기술 → 그 기술을 쓰는 다른 프로젝트. 데이터 규모는 한 사람 분량(수천 노드 이하)이다.

## 선택지

1. **PostgreSQL + 재귀 CTE**: 이미 익숙하고 운영 부담이 적다. 하지만 다단계·양방향 탐색 쿼리가 길어지고, 관계 타입마다 테이블이나 type 컬럼 설계가 필요하다.
2. **PostgreSQL + Apache AGE**: Cypher를 쓸 수 있지만 확장 설치가 필요하고, 생태계와 문서가 얇다.
3. **Neo4j 5 Community**: 그래프 탐색이 1급 기능이다. 가변 길이 패턴(`-[*1..2]-`), fulltext 인덱스(cjk 분석기), Testcontainers 모듈을 모두 기본 제공한다.

## 결정

Neo4j 5 Community를 쓴다.

## 결과

- `get_context`가 쿼리 하나(`MATCH p = (c)-[*1..depth]-(:Entity)`)로 끝난다.
- Community 에디션 제약: 노드 키(복합 유니크) 제약이 없다. 그래서 `(type, normName)`을 `key` 속성 하나로 합쳐 단일 유니크 제약을 건다([ADR-0005](0005-entity-identity-and-aliases.md)).
- Neo4j는 map을 속성으로 저장할 수 없다. 그래서 속성 이력(`Revision.changes`)은 JSON 문자열로 저장한다.
- 홈 k3s 클러스터에 올릴 때 메모리가 제약이다. 로컬 compose에서 heap 512m, pagecache 256m로 시작한다.
