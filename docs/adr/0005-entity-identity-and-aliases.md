# ADR-0005: 엔티티 식별은 (타입, 정규화 이름) + alias

- 상태: Accepted
- 날짜: 2026-10-19

## 맥락

LLM은 같은 대상을 매번 다르게 부른다: "k8s", "Kubernetes", "쿠버네티스". 반대로 다른 대상이 같은 이름을 가질 수도 있다. 예를 들어 기술 "Kafka"와 프로젝트 "Kafka"가 그렇다.

## 결정

- 식별자 `key = "<Type>:<normName>"`. `normName`은 NFKC → casefold → 공백 정리 결과다(`ＫＡＦＫＡ` → `kafka`).
- `aliases`를 두고, 이름 해석 시 `normName`과 `aliasKeys`를 함께 본다.
- 이미 있는 엔티티를 다른 표기로 upsert하면 새로 만들지 않고 기존 엔티티를 갱신한다. 그 표기는 alias로 추가한다.
- 같은 타입 안에서 alias가 다른 엔티티와 겹치면 거부한다.
- 이름만으로 여러 타입이 걸리면 `AmbiguousEntity` 에러로 후보를 보여준다. 호출자는 `Project:Kafka`처럼 타입 접두사로 고른다.

## 결과

- Community 에디션에서도 유니크 제약 하나로 중복 생성을 막는다.
- 정식 이름 변경(rename)은 아직 없다. 필요해지면 `key`를 바꾸는 별도 툴이 필요하다.
- 동명이인 같은 같은 타입 내 동명 엔티티는 구분할 수 없다. 개인 그래프 규모에서는 이름에 구분자를 넣는 것("Alex (회사)")으로 충분하다고 판단했다.
