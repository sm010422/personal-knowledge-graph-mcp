# ADR-0011: 백업은 Bolt로 논리 덤프 → rclone crypt로 암호화 → Backblaze B2

- 상태: Accepted
- 날짜: 2026-10-27

## 맥락

클러스터 Neo4j가 **유일한 사본**이다. PVC는 `local-path`라 k3s-master VM 디스크에만 있다. VM이나 홈서버 Mac 디스크가 망가지면 복구할 방법이 없다. 실제 개인 데이터를 쌓기 전에 백업이 있어야 한다.

조건은 이렇다.
- Neo4j **Community**다. `neo4j-admin database dump`는 DB를 멈춘 상태에서만 된다(온라인 백업은 Enterprise 기능).
- ArgoCD가 `selfHeal: true`다. CronJob이 StatefulSet을 0으로 줄여도 ArgoCD가 바로 되돌린다.
- 데이터는 개인 정보다. 백업 저장소 운영자도 내용을 볼 수 없어야 한다.
- 홈서버 전체(정전, 디스크 고장)를 잃어도 살아남아야 한다. 같은 집 안의 다른 디스크는 답이 아니다.
- 비용 0원이 목표다. 데이터는 많아야 수십 MB다.

## 선택지

### 덤프 방식
1. **`neo4j-admin database dump`**: 물리 덤프라 가장 충실하다. 하지만 DB를 멈춰야 하고, 멈추려면 ArgoCD 자동 동기화를 끄거나 StatefulSet 바깥에서 볼륨을 다뤄야 한다. 매일 몇 분씩 서비스가 끊긴다.
2. **APOC `apoc.export.cypher.all`**: 무중단이다. 하지만 Neo4j에 플러그인을 켜고 설정을 바꿔야 한다. 결과가 Cypher 스크립트라 복원도 APOC과 `cypher-shell`에 의존한다.
3. **Bolt로 직접 논리 덤프 (서버 이미지에 `pkg-mcp-backup` 추가)**: 무중단이고 Neo4j 설정을 바꾸지 않는다. 이미 있는 드라이버와 이미지를 그대로 쓴다. 대신 형식과 복원 코드를 직접 관리해야 한다.

### 저장 위치
1. 다른 노드의 PVC: 같은 홈서버 안이라 홈서버를 잃으면 같이 잃는다.
2. 홈서버 Mac 디스크: VM 장애는 견디지만 Mac 디스크 고장과 정전은 못 견딘다.
3. **외부 S3 호환 스토리지**: Cloudflare R2(결제 수단 필요)와 Backblaze B2(카드 없이 10GB 무료) 중 **B2**를 골랐다.

### 암호화
1. 저장소의 서버 측 암호화(SSE-B2)만 사용: 저장소 운영자는 평문을 볼 수 있다.
2. age/openssl로 직접 암호화한 뒤 업로드: 업로드 도구가 따로 필요하다.
3. **rclone crypt**: 암호화(NaCl secretbox, 인증 포함), 업로드, 오래된 백업 정리를 이미지 하나로 처리한다.

## 결정

덤프는 3번(Bolt 논리 덤프), 저장은 B2, 암호화는 rclone crypt다.

- **형식**: gzip JSON Lines. header → 노드 → 관계 → trailer 순서다. trailer에 개수를 적어서 잘린 파일은 복원 단계에서 거부한다. 날짜·시간 속성은 `{"$date": "..."}`처럼 태그를 붙여서 복원할 때 같은 Neo4j 타입으로 돌아온다(문자열로 바뀌지 않는다).
- **일관성**: 노드와 관계를 한 read 트랜잭션에서 읽는다. 그래서 관계의 양 끝 노드는 항상 같은 파일에 있다.
- **복원**: 빈 DB에만 복원한다. 기존 데이터와 섞지 않는다. 제약(`entity_key` 등)을 먼저 만들어서 중복이 있으면 바로 실패한다. 끝나면 개수를 trailer와 비교한다.
- **CronJob** (`k8s/backup-cronjob.yaml`): 매일 04:00 KST. init container(서버 이미지)가 emptyDir에 덤프하고, rclone 컨테이너가 암호화해서 올린 뒤 30일 넘은 백업을 지운다. 지우기는 업로드가 성공한 뒤에만 실행한다.
- **B2 설정**: rclone의 b2 백엔드에 `hard_delete`를 켠다. B2는 기본적으로 지운 파일을 숨김 버전으로 남겨서 용량을 계속 차지하기 때문이다. 앱 키는 이 버킷 하나에만, 읽기/쓰기 권한으로 만든다.
- **NetworkPolicy**: `app: personal-kg-backup` 파드만 Bolt에 추가로 허용한다.

## 결과

- 장점: 무중단이다. Neo4j 설정을 바꾸지 않는다. 백업 파일은 B2에서도 암호문이다. 같은 export/restore 코드를 Testcontainers 통합 테스트(`tests/integration/test_backup.py`)로 검증한다.
- **암호 문구를 잃으면 백업 전체가 쓸모없다.** 암호 문구는 클러스터 Secret과 로컬 `.env.backup`에 있다. 홈서버와 이 Mac을 동시에 잃는 경우를 대비해 비밀번호 관리자에 따로 보관해야 한다.
- 파일 이름(타임스탬프)은 암호화하지 않는다. 이름으로 오래된 백업을 정리하기 위해서다. 이름에는 개인 정보가 없다.
- 백업 작업이 실패해도 지금은 알림이 없다. Phase 3의 다운 알림(TODO 7-1)에서 함께 다룬다.
- 30일 동안 매일 빈 DB나 망가진 DB를 백업하면 정상 백업이 모두 밀려날 수 있다. 데이터가 적은 동안은 받아들인다. 필요해지면 "최소 N개 유지" 규칙을 추가한다.
- 데이터가 커지면(수백 MB 이상) 복원할 때 메모리에 모두 올리는 방식을 스트리밍으로 바꿔야 한다.
- 커스텀 형식이라 이 레포의 `pkg-mcp-backup`으로만 복원할 수 있다. 형식이 바뀌면 `version`을 올리고 이전 버전 읽기를 유지한다.
